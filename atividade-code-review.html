src/token.js (corrigido)
/**
 * Utilidades de token de acesso usadas pela tela de login.
 * Formato esperado: prefixo "tk_" + 16 caracteres [a-z0-9] (19 no total).
 */
export const PREFIXO = 'tk_';
export const TAMANHO = 19;

/** Remove espaços extras e padroniza para minúsculas. */
export function normalizaToken(valor) {
  if (typeof valor !== 'string') return '';
  return valor.trim().toLowerCase();
}

/** Oculta o token para exibição: tk_a1b2************ */
export function mascaraToken(valor) {
  const token = normalizaToken(valor);
  if (token.length <= 7) return token;
  return token.slice(0, 7) + '*'.repeat(token.length - 7);
}

/**
 * Verifica se o valor é um token de acesso válido.
 * Nunca lança erro: vazio, null ou undefined retornam false.
 */
export function validaToken(valor) {
  const token = normalizaToken(valor);
  if (!token.startsWith(PREFIXO) || token.length !== TAMANHO) return false;
  return /^[a-z0-9]{16}$/.test(token.slice(PREFIXO.length));
}

Respostas bloqueadas

Etapa 1O problema da revisão

O que está faltando nessa revisão?

  • Do lado do autor: descrição da PR (o que foi feito, por que, como testar) e uma mensagem de commit que diga algo. “ajustes” não informa nada.
  • Do lado do revisor: dizer onde está o problema (arquivo e linha), por que é um problema, o que fazer e se aquilo bloqueia ou é só sugestão.
  • Do lado do time: critérios combinados para aprovar ou pedir mudança.

O problema está só no código?

Não. Está também no processo (sem modelo de PR, sem checklist, sem checagem automática) e na comunicação dos dois lados: a PR chega sem contexto e o comentário chega sem conteúdo.

Como isso pode gerar conflito no time?

“Tá ruim. Refaz.” soa como julgamento da pessoa. O autor fica na defensiva, não sabe o que corrigir e refaz no escuro; surgem idas e vindas, atraso e retrabalho. Com o tempo, as pessoas evitam abrir PR ou passam a aprovar sem ler para não brigar.

Rubrica · 1,0 ponto

0,5: cita pelo menos duas faltas (contexto da PR e comentário sem motivo/sugestão). 0,25: reconhece que o problema também é de processo/comunicação. 0,25: descreve um efeito concreto no time (retrabalho, atrito, atraso). Resposta só “faltou educação” = 0,25 no máximo.

Etapa 2O mínimo de uma boa PR

Por que isso ajuda quem revisa?

O revisor entende o objetivo antes de ler o diff, sabe exatamente como testar e consegue julgar se o código faz o que promete. A revisão fica mais rápida e focada, e a PR vira documentação da decisão no histórico.

O que acontece quando essas informações não existem?

O revisor precisa adivinhar a intenção ou perguntar (mais ciclos). Pode aprovar algo que não entendeu, bloquear algo por engano ou testar o caso errado. Meses depois, ninguém sabe por que a mudança foi feita.

Rubrica · 1,5 ponto

0,5 por seção preenchida em revisao/PR-descricao.md: “O que foi feito” cita arquivos/funções; “Por que” traz a necessidade; “Como testar” tem passos que outra pessoa consegue repetir e o resultado esperado. Seção vazia ou genérica (“testei e funciona”) = 0.

O que diferencia uma sugestão de um bloqueio?

O impacto. Bloqueio afeta funcionamento, segurança ou a capacidade de verificar a mudança (bug, dado sensível exposto, falta de teste do caso principal, checagem automática falhando). Sugestão é preferência de estilo ou legibilidade: o código funciona sem ela e ela pode virar uma tarefa futura.

Quando usar LGTM?

Quando a mudança cumpre o objetivo descrito, as checagens automáticas passam, o caso principal está testado e não há risco conhecido. Sugestões pendentes não impedem: dá para aprovar e deixar os comentários.

Quando pedir um change-request?

Quando existe bug ou risco real, falta teste do caso principal, o lint ou os testes falham, há dado sensível exposto ou a mudança não faz o que a PR promete.

Etapa 4Comentários que ajudam

Qual comentário ajuda mais?

O B. Diz onde está o problema (o nome da função), por que é um problema (não deixa claro que valida o token) e qual é o próximo passo (renomear para algo mais específico). O A não dá nada para o autor fazer.

Qual tende a gerar menos atrito?

O B. Fala do código e não da pessoa, termina com uma pergunta que convida a conversar e mostra que o revisor leu com atenção.

O que um bom comentário precisa ter?

Local específico, motivo ou impacto, sugestão concreta, o peso deixado claro (bloqueante ou sugestão) e tom respeitoso focado no código. Quando couber, um elogio ao que está bom.

Três regras para bons comentários

  • Explique o motivo: diga o que pode dar errado ou o que fica difícil de entender.
  • Sugira uma melhoria: proponha nome, trecho ou teste.
  • Fale do código, não da pessoa: “esta função…” em vez de “você fez errado…”.

Como esse checklist ajuda o time?

Todo mundo revisa com o mesmo critério, inclusive quem está começando. O autor confere a própria PR antes de pedir revisão, então menos problemas chegam ao revisor e a revisão anda mais rápido. Fica mais difícil um bug óbvio, como o do valor vazio, passar despercebido.

Como ele evita discussões desnecessárias?

A decisão passa a se apoiar em critérios combinados antes, e não no gosto de quem revisa. O checklist separa o que bloqueia do que é sugestão, e as checagens automáticas tiram da conversa os pontos de padrão (como console.log). Com comentários respeitosos, sobra menos espaço para a defensiva.

/**
 * Utilidades de token de acesso usadas pela tela de login.
 * Formato esperado: prefixo "tk_" + 16 caracteres [a-z0-9] (19 no total).
 */
export const PREFIXO = 'tk_';
export const TAMANHO = 19;

/** Remove espaços extras e padroniza para minúsculas. */
export function normalizaToken(valor) {
  if (typeof valor !== 'string') return '';
  return valor.trim().toLowerCase();
}

/** Oculta o token para exibição: tk_a1b2************ */
export function mascaraToken(valor) {
  const token = normalizaToken(valor);
  if (token.length <= 7) return token;
  return token.slice(0, 7) + '*'.repeat(token.length - 7);
}

// Checagem automática simples (sem dependências), usada no CI e localmente.
//   ERRO  -> bloqueia (código de saída 1): console.log esquecido
//   AVISO -> não bloqueia: nome de função com menos de 4 caracteres
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';

const arquivos = ['app.js', ...readdirSync('src')
  .filter((nome) => nome.endsWith('.js'))
  .map((nome) => join('src', nome))];

let erros = 0;
let avisos = 0;

for (const caminho of arquivos) {
  readFileSync(caminho, 'utf8').split(/\r?\n/).forEach((linha, i) => {
    const onde = `${caminho}:${i + 1}`;
    if (/console\.log\(/.test(linha)) {
      erros++;
      console.log(`ERRO  ${onde}  console.log esquecido (pode expor dados, como o token)`);
    }
    const funcao = linha.match(/function\s+([A-Za-z_$][\w$]*)/);
    if (funcao && funcao[1].length < 4) {
      avisos++;
      console.log(`AVISO ${onde}  nome de função pouco descritivo: "${funcao[1]}"`);
    }
  });
}

console.log(`\nResultado: ${erros} erro(s), ${avisos} aviso(s) em ${arquivos.length} arquivo(s).`);
process.exit(erros > 0 ? 1 : 0);

const http = require('http');
const fs = require('fs');
const path = require('path');

const RAIZ = __dirname;
const TIPOS = {
  '.html': 'text/html; charset=utf-8',
  '.css': 'text/css; charset=utf-8',
  '.js': 'text/javascript; charset=utf-8',
  '.json': 'application/json; charset=utf-8',
  '.md': 'text/plain; charset=utf-8',
  '.svg': 'image/svg+xml',
  '.png': 'image/png',
  '.ico': 'image/x-icon'
};

let porta = Number(process.env.PORT) || 8080;
const portaMaxima = porta + 10;

const servidor = http.createServer((req, res) => {
  const url = decodeURIComponent(req.url.split('?')[0]);
  const arquivo = path.normalize(path.join(RAIZ, url === '/' ? 'index.html' : url));
  if (!arquivo.startsWith(RAIZ)) {
    res.writeHead(403);
    return res.end('Acesso negado');
  }
  fs.readFile(arquivo, (erro, dados) => {
    if (erro) {
      res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' });
      return res.end('Não encontrado: ' + url);
    }
    res.writeHead(200, {
      'Content-Type': TIPOS[path.extname(arquivo).toLowerCase()] || 'application/octet-stream',
      'Cache-Control': 'no-store'
    });
    res.end(dados);
  });
});

servidor.on('error', (erro) => {
  if (erro.code === 'EADDRINUSE' && porta < portaMaxima) {
    porta++;
    servidor.listen(porta);
  } else {
    console.error('Falha ao iniciar o servidor: ' + erro.message);
    process.exit(1);
  }
});

  fs.writeFileSync(path.join(RAIZ, '.preview-port'), String(porta));

Use antes de dar LGTM ou pedir mudanças (change-request).

- [ ] **A mudança está clara?** A PR tem "o que", "por que" e "como testar"; os commits têm mensagens descritivas.
- [ ] **Há risco de erro?** Entradas vazias, nulas ou inesperadas foram tratadas; nada de dados sensíveis em log.
- [ ] **É possível testar?** Existe teste para o caso principal e as checagens automáticas (lint + testes) passaram.
- [ ] **O comentário está respeitoso?** Fala do código, explica o motivo e sugere um caminho.

- Todos os itens OK, só sugestões pendentes -> **LGTM**.
- Qualquer risco de erro, falta de teste do caso principal ou checagem automática falhando -> **change-request**.

function Registrar {
  param([string]$Passo, [string]$Status, [string]$Detalhe = '', [string]$Correcao = '')
  $Script:Resultados.Add([pscustomobject]@{ Passo = $Passo; Status = $Status; Detalhe = $Detalhe; Correcao = $Correcao })
  $cor = @{ OK = 'Green'; ESPERADO = 'Cyan'; AVISO = 'Yellow'; FALHA = 'Red'; IGNORADO = 'DarkGray' }[$Status]
  Write-Host ('[{0,-8}] {1}' -f $Status, $Passo) -ForegroundColor $cor
  if ($Detalhe) { Write-Host ('           ' + ($Detalhe -split "`n")[0]) -ForegroundColor DarkGray }
}

function Executar-Passo {
  param([string]$Nome, [scriptblock]$Acao, [string]$Correcao, [string[]]$Requer = @())
  foreach ($r in $Requer) {
    if (-not $Script:Disponivel[$r]) {
      Registrar $Nome 'IGNORADO' "Depende de um passo anterior que falhou ($r)." "Corrija primeiro o passo relacionado a '$r' e rode o script de novo."
      return $false
    }
  }
  try {
    $detalhe = & $Acao
    Registrar $Nome 'OK' ([string]$detalhe)
    return $true
  } catch {
    Registrar $Nome 'FALHA' $_.Exception.Message $Correcao
    return $false
  }
}

function Invoke-Nativo {
  param([string]$Exe, [string[]]$Argumentos = @(), [switch]$PermitirFalha)
  $eap = $ErrorActionPreference
  $ErrorActionPreference = 'Continue'
  try {
    $saida = & $Exe @Argumentos 2>&1 | ForEach-Object { "$_" }
    $codigo = $LASTEXITCODE
  } finally {
    $ErrorActionPreference = $eap
  }
  $texto = (@($saida) -join "`n").Trim()
  if ($codigo -ne 0 -and -not $PermitirFalha) {
    throw ("'{0} {1}' terminou com código {2}. {3}" -f $Exe, ($Argumentos -join ' '), $codigo, $texto)
  }
  return [pscustomobject]@{ Codigo = $codigo; Saida = $texto }
}

const http = require('http');
const fs = require('fs');
const path = require('path');

const RAIZ = __dirname;
const TIPOS = {
  '.html': 'text/html; charset=utf-8',
  '.css': 'text/css; charset=utf-8',
  '.js': 'text/javascript; charset=utf-8',
  '.json': 'application/json; charset=utf-8',
  '.md': 'text/plain; charset=utf-8',
  '.svg': 'image/svg+xml',
  '.png': 'image/png',
  '.ico': 'image/x-icon'
};

let porta = Number(process.env.PORT) || 8080;
const portaMaxima = porta + 10;

const servidor = http.createServer((req, res) => {
  const url = decodeURIComponent(req.url.split('?')[0]);
  const arquivo = path.normalize(path.join(RAIZ, url === '/' ? 'index.html' : url));
  if (!arquivo.startsWith(RAIZ)) {
    res.writeHead(403);
    return res.end('Acesso negado');
  }
  fs.readFile(arquivo, (erro, dados) => {
    if (erro) {
      res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' });
      return res.end('Não encontrado: ' + url);
    }
    res.writeHead(200, {
      'Content-Type': TIPOS[path.extname(arquivo).toLowerCase()] || 'application/octet-stream',
      'Cache-Control': 'no-store'
    });
    res.end(dados);
  });
});

servidor.on('error', (erro) => {
  if (erro.code === 'EADDRINUSE' && porta < portaMaxima) {
    porta++;
    servidor.listen(porta);
  } else {
    console.error('Falha ao iniciar o servidor: ' + erro.message);
    process.exit(1);
  }
});

servidor.on('listening', () => {
  fs.writeFileSync(path.join(RAIZ, '.preview-port'), String(porta));
  console.log(`Preview em http://localhost:${porta}  (Ctrl+C para parar)`);
});

servidor.listen(porta);

/**
 * Utilidades de token de acesso usadas pela tela de login.
 * Formato esperado: prefixo "tk_" + 16 caracteres [a-z0-9] (19 no total).
 */
export const PREFIXO = 'tk_';
export const TAMANHO = 19;

/** Remove espaços extras e padroniza para minúsculas. */
export function normalizaToken(valor) {
  if (typeof valor !== 'string') return '';
  return valor.trim().toLowerCase();
}

/** Oculta o token para exibição: tk_a1b2************ */
export function mascaraToken(valor) {
  const token = normalizaToken(valor);
  if (token.length <= 7) return token;
  return token.slice(0, 7) + '*'.repeat(token.length - 7);
}

// valida
export function chk(t) {
  console.log('token recebido:', t);
  const v = t.trim().toLowerCase();
  const corpo = v.split('_')[1];
  return corpo.length === 16 && v.startsWith(PREFIXO) && v.length == TAMANHO && /^[a-z0-9]+$/.test(corpo);
}
